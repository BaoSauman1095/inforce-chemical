## 3. Фото товарів Ocean Invest — 33 з 33 (100%)

Усі товари Ocean Invest мають реальні фото. Механізм:

- Файли лежать у `public/products/{slug}.webp` (напр. `public/products/baal-bt.webp`)
- `lib/product-images.ts` — реєстр `PRODUCT_PHOTO_SLUGS` (Set слагів, у
  яких є реальне фото) + функція `productPhotoSrc(slug)`, яка повертає
  шлях або `null`
- `components/ProductCard.tsx`, `components/ProductGallery.tsx`,
  `components/RelatedProducts.tsx` — усі перевіряють `productPhotoSrc()` і
  рендерять `next/image`, якщо фото є, інакше `ImagePlaceholder` (як і
  раніше для решти брендів без фото)
- **Щоб додати фото новому товару**: покласти файл
  `public/products/{slug}.webp`, додати `"slug"` у `PRODUCT_PHOTO_SLUGS` у
  `lib/product-images.ts` — більше нічого чіпати не треба

### 3.1 Дизайн галереї (після кількох ітерацій фідбеку)

- `ProductGallery.tsx` — квадратний блок (`aspect-square`), фото через
  `object-contain` без padding, **без кліку/зуму** (кнопку "Збільшити фото"
  + модалку прибрано повністю за проханням користувача — тепер це простий
  server component, не `"use client"`)
- **Спроба #1 обрізати білі/прозорі поля навколо товару на самих фото була
  відкотена користувачем** ("херня") — НЕ повторювати той самий підхід.
  Деталі невдалої спроби: фото мають альфа-прозорість (не білий колір!)
  навколо пляшки; `sharp .trim()` з правильним alpha-aware фоном коректно
  обрізав кожне фото до ~70-90% заповнення кадру (замість ~50%) — технічно
  спрацювало, зображення стали більшими — але користувачу результат не
  сподобався візуально. Файли повернуто до оригінального стану (PR #10
  revert). Якщо повертатись до цієї ідеї — обговорити з користувачем
  конкретний бажаний результат ПЕРЕД тим, як обробляти всі 33 файли,
  можливо показати приклад на 1 фото спочатку.
- Іконки культур: `lib/crop-icons.ts` — `cropIcon(cropName)` мапить
  ключові слова (кукурудза→🌽, соняшник→🌻, ріпак→🌼, соя→🫘, горох→🫛 і
  т.д.) на emoji, фолбек 🌱 для нерозпізнаного (напр. "Пари", "Землі не

### 6.1 Правило автономного мержу — узгоджено з користувачем

- **Заміна demo-даних бренду на реальні в `lib/catalog-data.ts`** — гілка
  → PR → **мерж одразу, без питання підтвердження**. Це явно попросив
  користувач: "для кожного бренду сам створюй PR і сам одразу мержи його,
  без очікування мого підтвердження" (21.08.2026, після встановлення `gh`).
- **Усе інше** (компоненти, зображення/бінарні файли, конфіги, UI-правки)
  — гілка → PR → **чекати явного "мержи" від користувача** перед мержем.
  Підтверджено практикою цієї сесії: PR #7, #8, #9, #10, #11 (усі
  не-каталогові) — на кожен користувач окремо писав "мержи" перед тим, як
  його мержили.
- Після кожного мержу: `git checkout main && git pull origin main` перед
  тим, як починати нову гілку — щоб кожна нова гілка форкалась від
  актуального `main`.
- Кожна нова зміна — **окрема гілка**, не комітити напряму в `main`.

## 11. Важливі файли для перевірки

- `lib/catalog-data.ts` — усі 178 товарів (джерело даних каталогу)
- `lib/product-images.ts` — які товари мають реальне фото
- `lib/crop-icons.ts` — emoji для пілюль культур
- `.env.local` — змінні середовища (не в git)
- `package.json` — залежності (Next.js 14.2.35, React 18.3.1, Framer
  Motion, Zod). **Примітка**: під час роботи з фото тимчасово ставився
  `sharp` через `npm install sharp --no-save` для обрізки зображень —
  видалено (`npm uninstall sharp`) після відкату, `package.json`/lock не
  зачеплені
- `next.config.mjs` — конфіг Next.js (security-заголовки, images formats)
