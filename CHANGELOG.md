## [Unreleased]

### Added
- Початкова версія сайту IN FORCE CHEMICAL на Next.js 14 (App Router) +
  TypeScript + Tailwind CSS за наданим HTML-макетом.
- Секції: Header (sticky, десктоп/мобільна навігація), Hero, Каталог
  продукції (вкладки/пошук/фільтри/пагінація), "Наші результати в полі",
  Партнери, Форма заявки, Footer, плаваюча мобільна кнопка дзвінка.
- SEO: метадані/OG/Twitter Card, JSON-LD `Organization`, `sitemap.xml`,
  `robots.txt`, favicon і OG-картинка на льоту через `next/og`.
- API-маршрут `POST /api/send-notification`: Zod-валідація, honeypot,
  in-memory rate-limit, надсилання заявки в Telegram (MarkdownV2).
- Анімації на Framer Motion (поява секцій, меню, дропдауни, стани форми).
- Власний компонент `SmoothScroll.tsx` для плавної навігації по якорях.
- Документація: `README.md`, `.env.local.example`.

### Fixed
- **Каталог показував "Нічого не знайдено" після зміни вкладки** —
  `selectTab()` не скидав пошуковий запит (`query`), тож старий фільтр
  продовжував діяти на новій вкладці. Додано скидання `query` і кнопку
  "Скинути фільтри" в порожньому стані.
- **"Залипання" каталогу при перемиканні вкладок (React 18 StrictMode +
  Framer Motion)** — `AnimatePresence` з `mode="popLayout"` у сітці товарів
  ламався через подвійний виклик ефектів у dev-режимі: старі картки
  лишались у DOM поруч із новими. Замінено на повний remount сітки через
  `key={tab-group-brand-query}` замість `AnimatePresence`.
- **Скрол по якорях залипав при ручному скролі колесом/тачпадом під час
  анімації** — спершу прибрано глобальний CSS `scroll-behavior: smooth`
  (він змушував залипати взагалі будь-який скрол на довгій сторінці).
  Після повторного відтворення бага з'ясувалось, що й click-triggered
  `scrollIntoView({behavior:'smooth'})` сам по собі "бореться" з реальним
  вводом користувача і залипає посеред анімації. Остаточний фікс — власний
  `requestAnimationFrame`-цикл у `SmoothScroll.tsx`, що миттєво
  скасовується при будь-якому wheel/touchstart/keydown.
- **Білі тіні замість темних на картках** (`ProductCard`, кейси, форма) —
  кастомний колір `card: "#fdfcfc"` і кастомна тінь `boxShadow.card`
  в `tailwind.config.ts` мали однакове ім'я `card`; Tailwind автоматично
  генерує утиліту `shadow-{colorName}` для кожного кольору теми, і цей
  згенерований клас `.shadow-card { --tw-shadow-color: #fdfcfc }`
  переважав у каскаді над кастомною тінню. Тіні перейменовано в
  `panel`/`panelLg`, колізію усунено.
- **Плейсхолдер фото товару виглядав як яскраве біле "підсвічування"** на
  темному тлі сторінки — кольори діагональних смуг у
  `ImagePlaceholder.tsx` затемнено під загальну палітру.
- **Помилка порядку валідації honeypot-поля** — `company: z.string().max(0)`
  у Zod-схемі відхиляв заповнені ботами форми з 422 до того, як route
  handler встигав тихо повернути `{ok:true}`. Схему пом'якшено до
  `.optional().default("")`, логіка честной перевірки залишилась у
  route handler.
- **Function components cannot be given refs (попередження в консолі)** —
  проміжний крок діагностики каталогового бага; не було справжньою
  причиною, залишковий `forwardRef` на `ProductCard` більше не потрібен
  після переходу на remount-стратегію.

### Changed
- `next` оновлено `14.2.18 → 14.2.35` через критичну CVE в старій версії;
  разом з ним — `eslint-config-next` та `postcss` (`^8.5.26`).
- `.claude/launch.json`: додано `"autoPort": true`, щоб дев-сервер сам
  підбирав вільний порт, якщо 3000 зайнятий залишеним процесом попередньої
  сесії, замість падіння.

## Нотатки з розробки

- Rate-limit на `/api/send-notification` — in-memory, розрахований на один
  інстанс; для serverless з кількома інстансами розглянути Redis/Upstash.
- `app/icon.tsx` і `app/opengraph-image.tsx` працюють на `edge` runtime —
  це очікувано вимикає статичну генерацію саме для цих двох роутів.
