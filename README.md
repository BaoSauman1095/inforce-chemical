# IN FORCE CHEMICAL — сайт дистриб'ютора

Готовий до розробки проєкт на Next.js 14 (App Router) + TypeScript + Tailwind CSS.
Лендинг агродистриб'ютора: каталог з фільтрами, кейси, партнери, форма заявки
з надсиланням у Telegram.

> Поточний стан проєкту (що готово, що є демо-заглушкою) — у
> [PROJECT_STATUS.md](./PROJECT_STATUS.md). Історія змін і виправлених
> багів — у [CHANGELOG.md](./CHANGELOG.md).

## Стек

- **Next.js 14** (App Router, Route Handlers, `next/dynamic`, `next/font`, `next/og`)
- **TypeScript** (strict mode)
- **Tailwind CSS**
- **Framer Motion** — анімації появи/скролу, мобільне меню, дропдауни
- **Zod** — валідація форми на сервері
- **Telegram Bot API** — надсилання заявок

## Швидкий старт

```bash
npm install
cp .env.local.example .env.local
# впишіть у .env.local реальні TELEGRAM_BOT_TOKEN і TELEGRAM_CHAT_ID
npm run dev
```

Відкрийте http://localhost:3000. Якщо порт зайнятий (лишився процес від
попереднього запуску) — Next.js сам підбере наступний вільний (3001, 3002…),
дивіться яку адресу він виведе в терміналі.

Інші команди:

```bash
npm run build      # продакшн-збірка
npm run start       # запуск продакшн-збірки локально
npm run lint          # ESLint
npm run typecheck   # tsc --noEmit
```

## Налаштування Telegram-сповіщень

1. У Telegram напишіть **@BotFather** → `/newbot`, дайте боту ім'я — отримаєте
   `TELEGRAM_BOT_TOKEN`.
2. Дізнайтесь `TELEGRAM_CHAT_ID`:
   - для особистого чату — напишіть боту й відкрийте
     `https://api.telegram.org/bot<TOKEN>/getUpdates`, знайдіть `chat.id`;
     або скористайтесь **@userinfobot**;
   - для групи/каналу — додайте бота туди і зробіть те саме через `getUpdates`.
3. Впишіть обидва значення в `.env.local`.
4. На проді (Vercel/будь-який хостинг) додайте ці ж змінні в налаштування
   середовища — `.env.local` у git не потрапляє (див. `.gitignore`).

Усі форми сайту побудовані на спільних примітивах (`components/form/`) і
хуку `lib/useLeadForm.ts` — однакові поля, стилі, ханіпот, обробка статусів
і помилок. Заявки з форми (`components/ContactForm.tsx`) летять на
`POST /api/send-notification`, там проходять Zod-валідацію (`lib/validation.ts`),
після чого `lib/telegram.ts` форматує повідомлення (MarkdownV2, з екрануванням)
і шле його через Bot API. Помилки логуються на сервері (`console.error`) і
не показують користувачу деталі — лише дружнє повідомлення. Є прихований
honeypot-інпут (`company`) — прості боти, що заповнюють приховані поля,
отримують тихий "успіх" без реального надсилання. Ще є мінімальний
in-memory rate-limit (5 запитів/хв з IP) — достатньо для одного інстансу,
для serverless з кількома інстансами розгляньте Upstash/Redis.

## Кошик і замовлення

Кошик живе в `components/CartProvider.tsx` (React-контекст) і переживає
перезавантаження через `localStorage`. У сховищі лежать лише `slug`,
упаковка й кількість — назви та ціни щоразу беруться з каталогу, тож
оновлення прайсу одразу видно в кошику, а зниклі з каталогу позиції тихо
відпадають замість того, щоб потрапити в замовлення.

Панель має три кроки: список позицій, оформлення (ім'я й телефон) і подяка.
Форма винесена на окремий крок, щоб на телефоні список отримав усю висоту —
разом із підсумком і полями внизу на нього лишалось вікно під 2–3 картки.
Подяку показує саме панель, а не форма: очищення кошика після успішної
відправки розмонтувало б форму разом із повідомленням.

Оформлення (`POST /api/cart-order`) приймає той самий мінімум — посилання
на позиції плюс ім'я й телефон. Назви, упаковки та суми сервер підставляє
сам через `resolveOrderItems` (`lib/products.ts`), тому підмінити ціну в
запиті неможливо. Далі `lib/telegram.ts` збирає повідомлення зі списком
позицій і підсумком.

Ціни в каталозі — індикативні з прайсу «Розрахунок 2026» (колонка «Індикативна
ціна, $/Євро без ПДВ»), переведені в гривню за курсом із шапки прайсу
(USD 44, EUR 51) і з ПДВ 20%. Курс зашитий у вже порахованих числах, тож при
його зміні прайс треба перерахувати заново, а не правити коефіцієнт у коді.

Ціна упаковки рахується в `packTotalPrice` (`lib/utils.ts`): для суб-одиничних
пачок («500 г» при одиниці «кг», «п.о.») `price` — уже готова сума, для решти
це ставка за кг/л, і сума = число з мітки × ставка. Позиції без ціни
показуються як «за запитом» і в підсумок не входять.

## Фільтр за культурами

`lib/crops.ts` тримає список культур, за якими фільтрується каталог. У полі
`crops` товарів назви записані так, як у реєстрі препаратів — «Пшениця
озима», «Пшениця яра», «Зернові колосові» — тож фільтр працює не за точним
збігом рядків, а за регулярним виразом `match`: один пункт списку збирає всі
варіанти написання. Позиції, зареєстровані «на всі культури» (ад'юванти,
прилипачі), потрапляють під будь-яку обрану культуру.

Фільтр показується на вкладках «Добрива» і «Захист рослин». На «Насінні»
його немає навмисно: там культура — це і є категорія (Соняшник, Кукурудза),
тож окремий список лише дублював би вибір категорії. Обрана культура
переживає перемикання вкладок — бренди й категорії в кожній вкладці свої,
а культура та сама.

Щоб додати культуру, допишіть запис у `CROP_FILTERS`. Пункти без жодної
позиції на поточній вкладці в меню не показуються, категорії, порожні для
обраної культури, зникають зі свого списку, а якщо зникає вже обрана
категорія — вибір категорії скидається. Так фільтр не заводить у порожній
каталог.

## Зона натискання дрібних контролів

Плашки фасувань (38×25 px на картці каталогу) і «−/+», хрестики в кошику
та модалках (32×32) менші за рекомендовані 44 px для пальця. Збільшувати
їх візуально нема куди — на картці це підпис під назвою товару, — тому
клас `.tap-44` (`app/globals.css`) розширює саму зону натискання
невидимим `::after`, більшим за кнопку й центрованим по ній. Вигляд не
змінюється.

Правило загорнуте в `@media (pointer: coarse)`: на десктопі невидима зона
перехоплювала б кліки мишею повз кнопку, а там влучати й так нічого не
заважає. Сусідні плашки одна в одної натискань не крадуть — між ними
лишається достатньо місця.

## Ряд фільтрів каталогу

Бренд, культура й категорія — три однакові випадні списки
(`CatalogFilterMenu`), а не плитки. Плитки категорій на телефоні займали до
п'яти рядів: на вкладці ЗЗР із вісьмома категоріями ряд фільтрів виростав
до 324 px і закривав собою перші картки товару. Списками той самий ряд —
99 px на телефоні й 44 px на десктопі.

Меню притискається до лівого краю своєї кнопки, а `align="right"` — до
правого. Це потрібно для середнього списку: ряд на телефоні вужчий за два
меню, тож ліве тримаємо зліва, а праве справа, інакше одне з них вилазить
за екран. При відкритті меню підтягує сторінку `scrollIntoView`, бо ряд
фільтрів стоїть посеред екрана й на невисоких телефонах список не вміщався
під нижній край вікна.

## Заміна демо-каталогу на реальні дані

Каталог лежить у `lib/catalog-data.ts` — масив груп із товарами по трьох
вкладках (`seeds`, `fert`, `prot`). Найпростіший шлях розвитку:

- вручну відредагувати цей файл;
- або підключити зовнішнє джерело (Google Sheets API, 1С-вивантаження,
  headless CMS) і генерувати `CATALOG` у build-time чи через
  `fetch` у серверному компоненті — структура типів у `lib/types.ts`
  лишається незмінною.

- Метадані, Open Graph, Twitter Card, `robots`, canonical — `app/layout.tsx`.
- `app/opengraph-image.tsx` і `app/icon.tsx` генерують PNG на льоту через

## Плавна навігація по якорях

Клік по посиланню `<a href="#section">` (шапка, кнопки "Детальніше",
"Показати ще" тощо) анімується власним кодом у `components/SmoothScroll.tsx`
через `requestAnimationFrame`, а не нативним `scrollIntoView({behavior:
'smooth'})` чи глобальним CSS `scroll-behavior: smooth`. Причина: на довгій
сторінці нативна анімація браузера може "заклинити", якщо користувач починає
крутити колесо/тачпад до того, як вона завершилась. Власна реалізація
скасовується миттєво при будь-якому реальному `wheel`/`touchstart`/`keydown`
— керування завжди повертається користувачу без затримки. Звичайний скрол
(колесо, тачпад, клавіші, смуга прокрутки) ніколи не перехоплюється —
анімується лише сам клік по якірному посиланню.

## Продуктивність

- `components/Catalog.tsx` завантажується через `next/dynamic` окремим
  чанком (зі скелетон-плейсхолдером), щоб не роздувати початковий бандл.
- Шрифти (Inter, Montserrat) через `next/font/google` — self-hosted,
  без runtime-запитів до Google Fonts, `display: swap`.
- Зображення оптимізуються `next/image` (коли підключите реальні фото).
- `next.config.mjs` вмикає gzip/brotli-compress і базові security-заголовки.

## Відомі обмеження

- `app/icon.tsx` і `app/opengraph-image.tsx` працюють на `edge` runtime —
  це вимкне статичну генерацію саме для цих двох роутів (очікувано,
  Next.js попереджає про це при білді; на сторінку це не впливає).
- `npm audit` показує high-severity попередження на **внутрішній** (вкладений
  у `node_modules/next`) postcss — це залежність самого Next.js 14, а не
  прямий ризик для цього проєкту. Критичну вразливість самого Next.js вже
  закрито (використовується остання патч-версія лінійки 14 — `14.2.35`).
  Перехід на Next.js 15/16 — окрема задача (App Router API місцями змінився).
- Rate-limit у `/api/send-notification` — in-memory, скидається при
  рестарті/на serverless з кількома інстансами не є суворим лімітом.
